## Dedup notes

- **MERGED — credentials predicate vacuity (2→1):** `verification.rs:281` (CRITICAL, live starbridge verifier) and `sdk/src/privacy.rs:768` (MED, SDK footgun) are the identical `verify_predicate_proof(&p, p.fact_commitment)` x==x defect at two call sites, with one shared fix (`verify_predicate_proof_third_party` + `facts_root`). Kept as one CRITICAL row with both sites; fixing the helper/pattern closes both. **Track the SDK site explicitly in the fix PR so the MED variant isn't left behind.**
- **Kept separate but same meta-pattern — "SDK path uses the non-canonical, permissive verifier":** the authorize-least-privilege bypass (`identity`) and the predicate forgery (`credentials`) are distinct mechanisms (Datalog dimension gate vs predicate STARK commitment) but share the root disease: a widely-used SDK entry point routes around the checks the canonical verifier enforces, and both launder the fail-open verdict into a STARK proof.
