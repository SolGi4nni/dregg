# VK-REGEN LOG — append-only audit trail of descriptor regen events

Every authorized descriptor install / provenance stamp appends one row
(written by `scripts/emit_descriptors.py`; see docs/VK-REGEN-CONTROLS.md).
Rows are never edited or removed; git history is the tamper-evidence.

## The `epoch` column and the ledger — and why the emit script cannot be the gate

`PersistentStore::CANONICAL_STATE_SCHEMA_EPOCH` (`persist/src/lib.rs`) is a **Rust constant that
any commit can bump**, while this file was **only ever appended to by `scripts/emit_descriptors.py`**.
The two diverged on 2026-08-01: `6441705e8` moved the epoch 20 → 21 without running an emit, the
row above it still read "Schema epoch UNCHANGED at 20", and nothing in the tree could say so — a
check placed inside the emit path would have reproduced that blind spot exactly. So the check is
keyed on the **constant**: `scripts/check-schema-epoch-log.py`, a row of `scripts/local-gates.sh`,
plus `dregg_persist::schema_epoch_log_row` — an in-crate test that reds for anyone who edits the
constant and runs `cargo test -p dregg-persist`.

Two machine-readable structures serve it, and a malformed one is a **failure, never a pass**:

- **The `epoch` column** on every event row below. `epoch:N` = the epoch in force once that row's
  change landed; `epoch:unchanged` = this row carries no epoch information; `epoch:unknown` = it
  cannot be determined from the record. The **last `epoch:N` row must equal the constant.**
- **The ledger** below: one row per value the constant has ever held in committed history. Its last
  row must equal the constant too, and every value `git` can see must appear in it.

⚠ **BACK-FILLED 2026-08-01, so this column is younger than the rows that carry it.** Values were
derived mechanically — `git show <that row's repo HEAD>:persist/src/lib.rs` — except for the four
rows that declare their own bump, which carry the value *after* the change (their recorded repo HEAD
predates their own bump commit). The 23 rows dated before 2026-07-23 are `epoch:unknown` and that is
not a hedge: the constant **did not exist** at their repo HEAD (it was introduced at 11 by
`99ecf54b8`, 2026-07-22).

⚠ **TWO ROWS OF PROSE IN THIS FILE ARE WRONG ABOUT THE EPOCH, and the column does not repeat them.**
The 2026-08-01T10:43:56Z row says "Schema epoch 16 -> 17"; the constant went **16 → 19** in one
commit (`f77496b65`, the commit that row describes). **No commit in this repository's history has
ever held 17 or 18** — `HORIZONLOG.md`'s "FLAG DAY: `CANONICAL_STATE_SCHEMA_EPOCH` 18 → 19" is wrong
in the same way, and `HORIZONLOG.md` says why in a parenthesis 100 lines later: "the 18 slot was
allocated to this change and then two sibling epochs interleaved while it was in flight". Prose
records what a lane *intended*; the column and the ledger record what the constant *did*.
