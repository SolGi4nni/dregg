# ⚑ WHY THIS FILE EXISTS. `scripts/check-no-degraded-felt.sh` is RED at HEAD and is SUPPOSED to
# be: two real wounds are in production and are deliberately NOT allowlisted, because suppressing
# them is the containment-below-the-bar move. But a gate that is permanently red cannot tell you
# that a THIRD fold just landed — the exit code was already 1. That is the "red as steady state
# hides everything" failure, and it is what this ledger closes.
#
# So there are two verdicts, and they are different questions:
#   scripts/check-no-degraded-felt.sh            -> "is the tree clean?"   RED (2 standing wounds)
#   scripts/check-no-degraded-felt.sh --ratchet  -> "did anything NEW land?" GREEN, until it isn't
#
# ⚠ THIS IS NOT A SUPPRESSION. Neither wound is allowlisted, neither is hidden, and the default
# invocation still fails. A row here does not excuse a fold; it RECORDS one, so the number can only
# be made smaller. Adding a row is not a way to make a new fold acceptable — it is a way to make a
# new fold ATTRIBUTABLE, and the gate refuses a row that grows.
#
# The gate reds when a producer goes ABOVE its row (a net-new fold), BELOW it (a stale row — retire
# the number when you repair, do not leave a row that can absorb a future fold), or carries folds
# with no row at all. So this file may only ever SHRINK, and TOTAL is one honest number.
#
