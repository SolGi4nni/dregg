# scripts/descriptor-anchor-inertness-baseline.txt — DECORATIVE PUBLIC INPUTS per served descriptor.
#
# A DECORATIVE anchor is a `pi_binding` column whose connected component in the
# constraint graph is a SINGLETON: it co-occurs with no other column in any gate body,
# boundary body, window-gate body, lookup tuple, hash site, transition or bus op. The
# proof carries the value; nothing in the circuit is about it.
#
# ⚑ THESE NUMBERS MAY ONLY GO DOWN. Regenerate with
#   scripts/check-descriptor-anchor-inertness.py --write-baseline
# and say in the commit WHICH anchor became load-bearing and by what gate.
#
# ⚠⚠ ONE ROW WENT UP AND THEN DOWN AGAIN, BOTH ON PURPOSE, ON THE SAME DAY — 2026-08-04.
# `dregg-solana-lightclient-verify::v1`: 11 → 19 → 10. Read the whole sequence before treating any
# single step as a regression or as a win; a bare column count is a bad summary of both moves.
#
#   * 11 → 19 (morning). FOUR columns LEFT the decorative set — the total-stake limbs became PI-bound
#     AND joined to the quorum chain, the FIRST columns in this census ever to stop being decorative.
#     TWELVE joined it: `ANCHOR_ROOT` was ONE column holding a 256-bit SHA-256 stake-table root (i.e.
#     compared at 31 bits, a colliding pair findable in 2^31) and became NINE radix-2^31 limbs binding
#     the whole root; the +8 new limbs were decorative for exactly the reason the single column was,
#     and the shifted BANK_ROOT/SLOT_COL account for the rest. **The count rose because a hash stopped
#     being truncated, not because a public input stopped being checked.**
#
#   * ⚑ 19 → 10 (this commit). The nine `.first` anchor-root limbs are DELETED. The descriptor
#     absorbed `dregg-solana-stake-table-fold::v1` — it is MULTI-ROW now, one row per stake-table
#     entry — and the light client's weak-subjectivity anchor is the fold's EIGHT `.last` output
#     lanes, which sit in the component that contains the whole trace. The denominator is the fold's
#     accumulator, `.last`-pinned, for the same reason. What remains decorative is the nine bank-root
#     limbs and the slot: carried by the proof, read by no gate.
#
# ⚑ THE METRIC IS COLUMN COUNT, AND COLUMN COUNT IS THE WRONG DENOMINATOR FOR "how much of this
# proof's public statement is unbound" — widening a root to bind it properly and publishing eight more
# unrelated values move it the same direction. It moved the RIGHT direction only when the root became
# DERIVED. Anyone tightening this gate should count BITS-OF-PUBLIC-STATEMENT-UNBOUND, or the
# decorative SHARE, not columns.
#
# ⚠ THIS FILE IS EDITED BY HAND FOR THAT ROW, NOT REGENERATED.
#
# ⚑ 2026-08-05 — THE TWO DARK BAZAAR ROWS WERE NEVER MINTED, AND NEITHER NEEDS TO BE. The note that
# stood here said `--write-baseline` would mint rows for `dark-bazaar-private-poa-n4k4::receipt8-v2`
# (8) and `dark-bazaar-private-poa-settlement-n4k4::transition-v3` (33), and that blessing them from
# here would be exactly the laundering this gate exists to refuse. It was right. Both were BOUND or
# DELETED instead, so both leave the census at zero rather than entering it:
#
#   * `::transition-v3` -> `::anchored-v4`. Its 33 split into two unlike halves and the split is the
#     whole repair. THIRTY-TWO were the lanes of the judge's input / successor / public-view /
#     receipt digests, UNREAD — no gate body, boundary body or lookup tuple named those columns —
#     while the descriptor's docblock said it "binds" them. They hash canonical JSON strings
#     (`DarkBazaarJudgeWire.digestString`), so no AIR over that four-row fixed-width trace can derive
#     them; publishing them was a statement the circuit could not make, and absorbing them as chip

#     eight ANCHOR lanes are published in their place — the image, under the deployed Poseidon2 chip,

#     forces Solana's. The THIRTY-THIRD was the visibility grade, forced to the constant 1 by a
#     one-column gate: a measurement artifact of "a unary gate joins nothing", not an unbound value,
#     and now stated positively as `visibility_pi_is_forced_to_the_proven_grade`.
#     Public inputs 55 -> 31, width 496 -> 480. VK rotates.

#   * `::receipt8-v2` is DELETED outright. Its 8 were the same unbindable receipt digest, and the
#     anchoring mechanism does NOT transfer: v2's whole public surface beyond those eight lanes is
#     the v1 statement, already published and already chip-derived, so an anchor over it would be
#     redundancy dressed as a binding. Its own Lean docblock had said the pins "do not by themselves

#     exist is publishing a value nothing can check does not get a baseline row; it stops.
